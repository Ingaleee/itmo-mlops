## Требования

| Инструмент | Назначение |
|---|---|
| Python 3.12 | Локальное обучение, API и тесты |
| Git | Исходный код |
| Docker с Compose | Проверка контейнеров |
| Helm и kubectl | Проверка chart и работа с Kubernetes |
| Bash | Сценарии деплоя; на Windows — WSL или Git Bash |

Версии Python-пакетов определены в файлах выбранной лабораторной. CI использует Python 3.12.15 и устанавливает инструменты из [скрипта](../scripts/install_ci_tools.sh).

Блоки `bash` в документации выполняются в Bash; на Windows используйте WSL или Git Bash. Python-команды также работают в PowerShell с интерпретатором выбранного окружения.

## Окружение лабораторной

Примеры выполняются из корня репозитория. Для второй лабораторной замените `lab1` на `lab2`.

### Linux, macOS или WSL

```bash
cd lab1
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pip check
```

### Windows PowerShell

```powershell
cd lab1
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pip check
```

В командах README `python` обозначает интерпретатор окружения лабораторной. На Windows без активации используйте `.\.venv\Scripts\python.exe`; для запуска API — тот же интерпретатор с `-m uvicorn`.

## Локальные адреса

| Проект | Python API | Docker API |
|---|---|---|
| Iris | `http://127.0.0.1:8000` | `http://127.0.0.1:18090` |
| Search | `http://127.0.0.1:8001` | `http://127.0.0.1:18080` |

Каждый API запускается в отдельном терминале из своего каталога. Новая лабораторная получает свободный порт, указанный в её README.

## Зависимости и артефакты

| Файл или каталог | Назначение |
|---|---|
| `requirements.lock` | Закреплённые runtime-зависимости, включая транзитивные |
| `requirements.txt` | Установка runtime из lock-файла |
| `requirements-dev.txt` | Runtime и инструменты тестирования |
| `model.joblib` / `artifacts/` | Сгенерированная модель или индекс |
| `evidence/` | Результаты локальных проверок |

После изменения модели пересоберите артефакт перед запуском API. Сгенерированные модели, окружения и временные отчёты не коммитятся. Краткие проверенные результаты публикуются в `docs/verification/`; полные отчёты CI доступны в Actions artifacts.

## Порядок проверки

1. Собрать модель или индекс командами проекта.
2. Выполнить тесты и контроль качества.
3. Запустить API и проверить контракт.
4. Собрать контейнер и повторить внешнюю проверку.

Тесты лабораторных запускаются из их каталогов: обе реализации используют Python-пакет `app`, поэтому проверяются отдельными процессами.

Корпус Search и контрольный набор хранятся раздельно. Контрольные запросы используются для оценки качества и не участвуют в обучении индекса.
