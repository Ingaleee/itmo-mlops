# Новая лабораторная

[Каталог проектов](../README.md)

Каждая лабораторная — самостоятельный проект в `labN/`. Её README позволяет понять задачу, запустить реализацию и проверить результат без чтения остальных лабораторных.

## Структура

```text
labN/
  README.md                # описание готовой реализации
  ASSIGNMENT.md            # исходные требования
  DEMO.md                  # снимки, видео и ссылки на исходные результаты
  app/                     # приложение
  scripts/                 # обучение, проверки и специфичные сценарии
  tests/                   # тесты
  data/                    # исходные данные, если нужны
  requirements.lock        # закреплённый runtime
  requirements.txt         # установка runtime
  requirements-dev.txt     # runtime и инструменты разработки
  Dockerfile               # сборка и runtime
  k8s/ или helm/           # конфигурация развёртывания
```

Состав зависит от задачи; создавайте только используемые каталоги. Сгенерированные модели, `artifacts/`, `evidence/` и окружения остаются вне Git.

Endpoints, запросы, ответы и ограничения ввода.

## Включение в репозиторий

1. Добавить проект и исходные требования в `labN/`.
2. Описать реализацию по каркасу; ссылки на общие инструкции заменяют их дублирование.
3. Добавить строку в таблицу корневого README.
4. Включить сборку, тесты и внешнюю проверку в CI. Использовать отдельные имена image, ресурсов и каталогов artifacts.
5. Добавить результаты проверки с указанием версии артефакта в `docs/validation.md` и краткий отчёт в `docs/verification/`.
6. Добавить галерею `DEMO.md`; медиа разместить в `docs/media/labN/`, проверяемые источники — в `docs/media/sources/`. Порядок описан в [инструкции](media/README.md).

README описывает текущее поведение и решения. История переписки, сроки, проблемы доступа и хронология исправлений в документацию проекта не входят.
