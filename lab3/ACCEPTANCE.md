# Критерии проверки Knowledge Portal

[Описание проекта](README.md) · [Контрольные вопросы](control-questions.json)

Критерии определены постановкой, а не текущей реализацией. Отдельная проверка SDK подтверждает транспорт; она не заменяет независимую проверку готового MCP-сервиса и весь путь от браузера до модели.

## Обязательные результаты

| Область | Действие | Ожидаемый результат и подтверждение |
|---|---|---|
| Корпус | Загрузить исходный JSON | 36 редакций, 35 ID, 6 разделов, 12 подразделов; валидные dates/status/visibility/path/links/replaces; SHA-256 исходного файла |
| Валидация | Повторить revision, anchor, JSON field; убрать visibility | Вход отклонён до индексации; экранированное имя JSON не скрывает дубликат |
| Индекс | Перестроить при открытом чтении | Новый файл проверен и опубликован атомарно; запрос использует целостный старый или новый generation |
| Поиск | Выполнить К01–К08 | Все необходимые пары ID/version найдены в top-5 уникальных карточек; альтернативы К08 учитываются как альтернативы |
| Фильтры | К01 по подразделу; К02 с архивом; К03 с черновиками | Действующая версия остаётся default; архив и черновики явно подписаны |
| Дерево | Пройти раздел → подраздел → редакция | Все записи доступны; две редакции M-05 открываются разными URL |
| Точное открытие | Открыть `/docs/M-05/2.0#s01` и архивную 1.1 | Версия не подменяется; якорь ведёт к соответствующей секции |
| MCP | Независимым SDK-клиентом вызвать initialize/list/call | Три tools имеют входные/выходные схемы; structuredContent валиден; отсутствие версии отличается от ошибки транспорта |
| RAG | Задать вопрос | 2–4 релевантных отрывка, единый снимок индекса, карта ссылок; URL строятся сервером |
| Ответ | Запросить факт без подтверждения; вернуть неизвестную ссылку от модели | Нет придуманного факта или URL; безопасные документы/выдержки и `search_only` |
| Два провайдера | Отдельно вызвать настоящий llm7.io и настоящую CPU-модель | Реальная генерация от каждого; mock не засчитывается как внешний провайдер или локальная модель |
| Cloud fallback | Включить 429, quota, 503, timeout, обрыв, повреждённый ответ | Тот же запрос уходит в local с теми же generation/context/source map; одна облачная попытка |
| Возврат в cloud | Дождаться паузы и разрешить 200 | Одна конкурентная half-open проба; после успеха следующий разрешённый запрос снова cloud |
| Retry-After | Вернуть секунды или HTTP date; убрать заголовок | Пауза вычислена корректно; без заголовка 429 начинает с 60 с |
| Квота | Вернуть документированную ошибку квоты | Классификация по телу; обычный 429 не называется квотой; пауза до reset либо 30 мин |
| Конфигурация | Вернуть 401, 403 без quota либо model_not_found | Оператор видит проблему настройки; временно local; возвращение после исправления и проверки |
| Приватность | Выбрать закрытый источник, приватный режим или сомнительную метку | Ноль облачных вызовов; вопрос, заголовки и производные закрытого контекста не уходят наружу |
| Внедрённая инструкция | Открыть оригинал закрытой карточки и спросить о методе атаки | Оригинал доступен локально; опасная цитата исключена из промпта; контрольный маркер не воспроизводится; модель не исполняет сеть/команды |
| Перегрузка | Занять слот и одно место ожидания; отправить третий запрос | Сверх лимита `search_only`; ожидание входит в общий CPU budget |
| Отмена | Разорвать запрос во время ожидания и генерации | Работа отменяется, слот снова доступен; поведение реального runtime замерено отдельно |
| Обе модели недоступны | Остановить/имитировать отказ генерации | Портал продолжает поиск и показывает источники с `search_only` |
| Kubernetes | Пересоздать Pod модели | Веса доступны, readiness восстановлена, отдельный запрос генерирует ответ без GPU |
| Изоляция | Проверить доступ к MCP | Браузер обращается только к portal; MCP ClusterIP, сервисный токен, проверка Origin; NetworkPolicy при поддержке CNI |
| Наблюдаемость | Выполнить cloud/local/search_only | request_id, route reason, latency и counts видны; текста вопросов/ответов, контекста и Authorization в обычных логах нет |
| Ресурсы | Записать idle и серию CPU-ответов | Requests/limits и фактические RAM/CPU/latency согласованы; нет заявления о производительности без замера |

## Стартовые ограничения

- MCP — 2 с, cloud — 12 с, CPU с очередью — 105 с; end-to-end 122 с. Исходный эксперимент с 75 с не вместил фильтрованный контрольный вопрос на ноутбуке. LOCAL_BUDGET_SECONDS допускает 15–180 с; общий timeout рассчитывается из CPU budget, cloud timeout и 5 с на MCP/служебные действия.
- Один слот CPU-генерации и одно место ожидания; одна реплика portal до определения общего владельца admission/circuit state. Несколько workers не должны независимо размножать заявленный предел.
- Контекст модели 2048 токенов; шаблон, вопрос и отрывки около 1500, ответ 120–160. Проверять конкретным токенизатором, а не подсчётом символов.
- Для 5xx/transport/invalid response стартовая пауза 30 с; для confirmed quota — известный reset либо 30 мин.
- Потоковая выдача отключена: fallback завершается до отправки ответа пользователю.

## Что необходимо для финальной проверки

Профиль `itmo-student-01`: квота 2600m CPU / 4G RAM. Основной стек требует 2200m / 3712Mi и запускается отдельно от полных профилей первых двух работ. Конфигурация описана в [профиле кластера](../docs/teaching-cluster.md), фактические результаты — в [проверках](../docs/validation.md#knowledge-portal).

Бесплатный API token получается в [кабинете llm7.io](https://dash.llm7.io/). Он хранится только в backend Secret. Перед реальной проверкой нужны доступная модель, короткая генерация и сверка поведения ошибок с [документацией провайдера](https://docs.llm7.io/). Синтетические сбои проверяются отдельным mock с фиктивным ключом; нельзя намеренно тратить всю настоящую квоту.

Настоящие провайдеры и Kubernetes проверяются отдельно. Доступ к API, успешный dry-run, публикация image и модельный HTTP probe не заменяют проверку полного пути и контрольных фактов.
